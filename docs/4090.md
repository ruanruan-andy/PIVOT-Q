# RTX 4090 Training and Evaluation

Run each job on one RTX 4090 with 24 GB VRAM. The original training entries remain
available. These entries use `single_gpu` names and retain both policies in host
RAM, with one complete policy resident on CUDA at a time. PS has 125 GiB host RAM;
allow sufficient RAM for both policies, quantization buffers and rollout caches.

Complete [environment and resource setup](../env/README.md), including local
checkpoints, quantization packs, tokenizer files, LIBERO-Plus assets and the
shared manifest. Run from the repository root:

```bash
source env/runtime/paths.sh
source "$CONDA_SH"
export OMP_NUM_THREADS=8 MKL_NUM_THREADS=8 OPENBLAS_NUM_THREADS=8
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
```

Transferred ModelScope packs may record an older checkout root. Register that
root explicitly during path setup; this relocates metadata paths while keeping
checkpoint/gate identity checks enabled:

```bash
python env/configure_paths.py "$PIVOT_Q_ROOT" --paths-only \
  --previous-root /lumos-vePFS/suzhou/Users/ruan/OPDQ --apply
source env/runtime/paths.sh
```

## Training protocol

| Setting | Adapter organization | Rollouts | Optimizer updates |
|---|---|---:|---:|
| GR00T + QuantVLA | One adapter per suite | 140 per suite | 700 per adapter |
| GR00T + HoloQ-VLA | One adapter per suite | 140 per suite | 700 per adapter |
| pi0.5 + QuantVLA | One shared adapter | 560 total | 700 total |
| pi0.5 + HoloQ-VLA | One shared adapter | 560 total | 700 total |
| OpenVLA-OFT + QVLA | One adapter per suite | 140 per suite | 700 per adapter |

The student controls every recovery rollout. Observations, student actions and
explicit diffusion noise (where applicable) are retained on CPU. The teacher
then replays those observations with the same noise and denoising schedule.
Teacher replay does not step the environment. Selection and all five optimizer
updates are completed before the next recovery group. Teacher replay restores
the surrounding Python, NumPy and PyTorch RNG states.

GR00T/QVLA update after each trajectory. pi0.5 collects four trajectories with
unchanged parameters, averages the four trajectory losses through gradient
accumulation, then makes five optimizer updates. Its suite order is Object,
Spatial, Goal, LIBERO-10, yielding 140 groups and 700 steps. Anchor sampling,
loss definitions, quantization precision, adapters and optimizer settings follow
the selected experiment configuration. FSD uses all valid states with uniform
weights; PIVOT-Q uses the original vulnerability selector.

GR00T stores frozen eval-mode backbone features on CPU and moves the backbone
off CUDA during action-head updates. QVLA uses the existing detached feature
cache. No predictions or autograd graphs are reused across optimizer updates.
The sequential collection order differs from the original multi-GPU protocol;
report this execution mode when comparing results.

## GR00T + QuantVLA / HoloQ-VLA

Activate `groot_test`. The launcher owns the simulator services and runs the
four suites sequentially. Each following command is a separate experiment:

```bash
conda activate groot_test
python scripts/train_single_gpu.py --config config/pivot_q.yaml --gpu 0
python scripts/train_single_gpu.py --config config/full_distill.yaml --gpu 0
python scripts/train_single_gpu.py --config omega_qvla/pivot_q/config/pivot_q.yaml --gpu 0
python scripts/train_single_gpu.py --config omega_qvla/pivot_q/config/full_distill.yaml --gpu 0
```

Use `--suites libero_spatial` for one suite, `--seed 0` for the training seed,
and `--dry-run` to inspect commands. Default service ports are 19600/19601.
Reissue the same command to resume the latest complete checkpoint. Final adapters:

```text
outputs/<quantizer>/groot_n1_5/<method>/train/seed-000/single_gpu/<suite>/final_adapter
```

### GR00T QuantVLA ablations

Use the same launcher with the existing experiment YAML, one command at a time:

```bash
python scripts/train_single_gpu.py --config config/random_sparse.yaml --gpu 0
```

Replace `random_sparse.yaml` with `uniform_sparse.yaml`,
`global_random_sparse.yaml`, `pivot_q_current_only.yaml`, `pivot_q_no_anchor.yaml`,
`pivot_q_a03_b07.yaml`, `pivot_q_a04_b06.yaml`, `pivot_q_a07_b03.yaml`, or
`pivot_q_a03_b07_no_anchor.yaml` for the corresponding experiment.

Each YAML retains its own selector, weighting and Anchor setting. These runs use
the existing `outputs/quantvla/groot_n1_5/ablations/...` roots, with a `single_gpu`
subdirectory under the training seed. Use the matching adapter for evaluation.

## pi0.5 + QuantVLA / HoloQ-VLA

```bash
conda activate lerobot_pi05
python pi05_quantvla/pivot_q/run_train_single_gpu.py \
  --config pi05_quantvla/pivot_q/config/pivot_q.yaml --gpu 0
python pi05_quantvla/pivot_q/run_train_single_gpu.py \
  --config pi05_quantvla/pivot_q/config/full_distill.yaml --gpu 0
python pi05_omegavla/training/run_train_single_gpu.py \
  --config pi05_omegavla/config/pivot_q.yaml --gpu 0
python pi05_omegavla/training/run_train_single_gpu.py \
  --config pi05_omegavla/config/full_distill.yaml --gpu 0
```

These are four alternatives to run sequentially. Defaults: service ports
19500/19501; training seed 0; 700 optimizer updates. `--max-rounds 1` stops after
one additional group and writes a resumable checkpoint; omit it for the full
budget. `--dry-run` prints the resolved configuration.

```text
outputs/<quantizer>/pi05/<method>/train/seed-000/single_gpu/
├── single_runtime.json
├── run.json
├── status.json
├── metrics.jsonl
├── checkpoints/step-000700/{adapter,trainer_state.pt,complete.json}
└── final_adapter -> checkpoints/step-000700/adapter
```

Reissue the command to resume; the saved optimizer, four logical streams, Anchor
buffers, schedule and RNG states are restored. This execution mode records its
own protocol signature. Start in a fresh directory when changing execution mode;
use `--output-dir` to distinguish it from a previous single-device run.
Training executes one action per inference; ordinary evaluation retains the
configured ten-action queue for pi0.5. The ten denoising steps are a separate
parameter and remain unchanged.

## OpenVLA-OFT + QVLA

Activate `oft_qvla`; the services use `libero_test`. Run from the integration
directory. This example trains the Spatial suite with PIVOT-Q:

```bash
conda activate oft_qvla
cd "$PIVOT_Q_ROOT/openvla-oft-qvla"
CUDA_VISIBLE_DEVICES=0 bash scripts/launch_with_services.sh train \
  --suite libero_spatial --plus-port 19700 --clean-port 19701 \
  --service-python "$(conda run -n libero_test python -c 'import sys; print(sys.executable)')" \
  -- python -m training.train_single_gpu --config configs/pivot_q.yaml \
     --suite libero_spatial --set environment.port=19700 --set environment.clean_port=19701
cd "$PIVOT_Q_ROOT"
```

Change both `--suite` arguments to `libero_object`, `libero_goal`, or `libero_10`
for another suite. Change `configs/pivot_q.yaml` to `configs/full_distill.yaml`
for FSD. Add `--set seed=0` to the worker arguments to choose the training seed.

The final per-suite checkpoint is
`outputs/qvla/openvla_oft/<method>/train/seed-000/<suite>/single_gpu/checkpoint-000140.pt`.
To resume one suite, add
`--set training.resume=/absolute/path/to/checkpoint-000010.pt` to the worker
command, retaining the same configuration and output. Services exit with the
launcher. Official QVLA/OFT source files are not modified.

## Ordinary evaluation

Use the existing evaluation entry with the exact new adapter path. Ordinary
success-rate evaluation loads one policy. Diagnostic teacher replay remains an
explicit separate choice in the original diagnostic documentation.

The unified launcher supports all five family names: `groot_quantvla`,
`pi05_quantvla`, `groot_holoqvla`, `pi05_holoqvla`, `openvla_oft_qvla`.
Activate the model's environment from the sections above. QVLA requires one
`--suite` per simulator service; run its four suites sequentially. The other
families accept `--suite all`. For example:

```bash
conda activate groot_test
python scripts/core_command/launch.py groot_quantvla pivot_q eval \
  --suite all --gpu 0 --seed 2026 --port 19800 --clean-port 19801 \
  --adapter-path 'outputs/quantvla/groot_n1_5/pivot_q/train/seed-000/single_gpu/{suite}/final_adapter' \
  --results-root outputs/quantvla/groot_n1_5/pivot_q/single_gpu \
  --resume
```

Change `--seed 2026` to `--seed 2027` or `--seed 2028` for another evaluation seed.

For pi0.5 supply the shared `single_gpu/final_adapter`; for QVLA supply the
suite-specific `single_gpu/checkpoint-000140.pt`. Replace `pivot_q` with
`full_distill` for FSD and use its matching checkpoint. Original and Quantized
use `fp_original` and `quant_original` without an adapter argument. For GR00T
QuantVLA ablations, retain `pivot_q` and pass the matching `--ablation` value.
Use separate results roots for these 4090 runs and keep the configured manifest,
action execution counts and evaluation seeds. `--dry-run` previews any command.
After complete evaluation, follow [seven-category aggregation](result_aggregation.md).

## Validation scope

Verification uses real local base models and quantization packs, real LIBERO
observations, teacher replay, five differentiable adapter updates, and optimizer
state serialization/restoration. Simulator reset/step and configuration/selector
checks are separate from full benchmark evaluation. Small validation runs do
not replace a complete 700-step experiment or a 560-episode success-rate report.

## Training progress

All five settings show tqdm training progress, elapsed time and ETA. GR00T and
OpenVLA-OFT count rollouts per suite; pi05 counts 140 rounds of four rollouts,
with rollout count, current suite and optimizer steps in the postfix. Resume
starts at the restored rollout/round and optimizer step. Teacher replay and
optimizer updates have separate temporary progress bars. ETA is based on
completed iterations in the current process and appears after progress is made.
The training budget, metrics and checkpoint formats are unchanged. Restarting
a process is necessary to load newly edited code; existing runs keep their
loaded version.
